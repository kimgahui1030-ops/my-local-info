## 2. 전체 구조 (구성 → 발행)

```
[1 소재] → [2 선택] → [3 카피] → [4 이미지] → [5 렌더] → [6 검수] → [7 발행] → [8 성과]
 collect.py   터진 글     제목5안·캡션   Pixabay/Pexels   HTML→JPEG     자동 체크     폰 수동 →     24h/72h 수치
 (완료)       그리드      facts 추출     /AI/업로드       1080×1350     + 사람 확인   브라우저 자동 → 프롬프트 개정
                                                                                    → API 예약
```

산출물은 게시물 하나마다 폴더 하나로 묶습니다.

```
out/<날짜>/<id>/
  cover.jpg  slide2.jpg ...   1080×1350 JPEG
  caption.txt                 그대로 붙여넣을 캡션
  credit.txt                  이미지 출처·라이선스
  meta.json                   원본 링크, 제목 후보, facts, 템플릿, 검수 결과, 발행 상태
```

이 폴더 규격을 모든 단계의 약속으로 두면, 앞 단계(누가 카피를 쓰는지)나 뒤 단계(어떻게 발행하는지)를 바꿔도 나머지는 고칠 필요가 없습니다.

## 3. 단계별 설계

### 3-1. 소재 (구성의 출발점)
- **소재 통로 1 (주력)**: `collect.py`가 매일 1회 벤치마크 계정을 돌고, 새로 "터진 글"(중앙값 2배 이상)만 후보로 올립니다. 가져오는 것은 **주제와 사실**이고, 사진과 문장은 가져오지 않습니다.
- **소재 통로 2 (보조)**: 해외 이슈 계정. 현재 realkhalilu 1개뿐이라 추가 확보가 과제입니다. Pubity·UNILAD·LADbible 계열은 검증이 필요합니다.
- **소재 통로 3 (선택, 이 저장소와 연결)**: `my-local-info`가 공공데이터에서 모으는 지역 행사·지원금 정보를 생활정보형 카드뉴스 소재로 씁니다. 공공데이터라 저작권 부담이 낮고, 사이트 유입 경로도 됩니다. 다만 화제성은 해외 황당뉴스형보다 낮을 가능성이 큽니다(추정).
- 한 번 쓴 원본에는 `used` 표시를 해서 중복 발행을 막고, 같은 소재 7일 내 재사용을 막습니다.

### 3-2. 구성 (한 게시물의 모양)
벤치마크 결론에 따라 **MVP는 표지 1장 + 긴 캡션**이고, 캐러셀은 옵션입니다.

| 형식 | 장 구성 | 쓰는 곳 |
|---|---|---|
| **A. 매거진형 1장** (기본) | 표지 1장: 사진 + 하단 40~45% 어두운 그라데이션 + 55% 지점 계정 라벨 + 65~80% 구간 흰색 굵은 2줄 제목, `[[강조]]` 노랑 | 해외 황당뉴스, 국내 이슈 |
| **B. 해외 이슈형** (수출용) | 표지 1장(좁고 굵은 대문자 3~4줄, 하단 검정, "SWIPE →") + 사진 2~3장 | 영어권 계정 확장 시 |
| **C. 정보형 캐러셀** | 표지 → 본문 3~7장(상단 이미지 + 하단 흰 카드: 번호·제목·강조문·본문) → 마지막 장 요약/CTA | 생활정보·지원금·체크리스트 |

정보형 캐러셀 기본 흐름은 `표지(훅) → 문제/상황 → 핵심 1~3 → 방법 → 요약 → CTA(저장·공유 유도)`이고, 장수는 5~8장을 권장합니다. 벤치마크 캐러셀 평균은 2.6~9장으로 편차가 큽니다.

### 3-3. 카피
LLM 호출 한 번으로 아래 JSON을 받습니다(DESIGN.md §3-3 규격 그대로).

```json
{
  "titles": [{"text": "티라노 장난감 집게로\n경찰 권총 [[30번]] 훔친 남자", "formula": "숫자", "score": 9}],
  "caption": "[제목]\n\n문단1…문단5",
  "image_queries": ["toy grabber claw", "police holster"],
  "ai_image_prompt": "…",
  "facts": ["플로리다", "30번"]
}
```

- **제목**: 2줄, 줄당 13~16자. 숫자·따옴표·결론 숨김 중 1~2개를 쓰고, `[[ ]]` 강조는 한 곳만. 후보 5개를 받아 사람이 고릅니다. 강의 A/B 결과에 따르면 제목만 바꿔도 조회수가 29~44배 차이 났습니다.
- **캡션 K (국내)**: `[제목]` + 배경 → 사건 → 놀라운 점 → 반응 인용 → 결말. 600~700자, 기사체, CTA·해시태그 없음.
- **캡션 G (해외/수출)**: 첫 줄을 질문으로 시작하고 사건을 요약합니다.
- **사실 고정**: 숫자·고유명사·장소는 원문 그대로 `facts`로 뽑아 검수에서 대조합니다. 과장은 금지합니다(금지 예시: "splashes 14 people" → "14명 참사").
- 윤문은 humanize-korean 규칙 요지를 프롬프트에 넣습니다.

### 3-4. 이미지
| 소스 | 언제 | 처리 |
|---|---|---|
| Pixabay·Pexels | 사물·동물·장소·일반 상황 | 키는 `.env`, 출처는 `credit.txt` |
| AI 생성 | 특정 사건 재현이 필요할 때 | 표지 하단에 "이해를 돕기 위한 AI 생성 이미지" 표기 |
| 직접 업로드 | 권리가 있는 사진 | — |

원본 게시물 사진은 기본적으로 쓰지 않습니다. 저작권 신고와 오리지널 정책(수익화 제외) 때문입니다.

### 3-5. 렌더
- HTML 템플릿(`templates/a_magazine.html` 등)에 데이터를 넣고 Playwright로 캡처해 **1080×1350 JPEG**로 저장합니다. 칼럼에 있던 `device_scale_factor` 방식을 쓰면 슬라이드별 PNG/JPEG를 한 번에 뽑을 수 있습니다.
- 폰트는 Pretendard를 로컬에 번들합니다(외부 CDN 의존 없음).
- 세이프존: 위아래 135px(1:1 크롭 안전선). 제목이 길면 글자 크기를 자동으로 줄입니다.
- 참고(확인 필요): 인스타그램은 2025년부터 프로필 그리드 썸네일을 세로형(3:4)으로 보여 주는 것으로 알고 있습니다. 4:5 표지는 그리드에서 좌우가 조금 잘릴 수 있으므로, 제목을 좌우 5% 여백 안쪽에 두는 현재 스펙을 유지하고 첫 발행 때 실제 그리드에서 한 번 확인합니다.
- Card News Studio v3의 템플릿 10종과 제목 엔진은 **디자인 참고 자산**으로 재활용합니다. 앱 자체를 주력으로 쓰려면 먼저 실제 브라우저 검증이 필요합니다.

### 3-6. 검수 게이트 (저장 전 자동)
제목 글자 수·줄 수, 세이프존 침범, `facts`가 캡션에 그대로 있는지, 금칙어(과장어·혐오 표현), 7일 내 중복 소재, 이미지 출처 기록 여부를 봅니다. 통과하지 못하면 저장을 막고 이유를 보여 줍니다. 최종 확인은 사람이 합니다.

### 3-7. 발행 (3단계로 올라감)
| 단계 | 방식 | 할 일 | 상태 |
|---|---|---|---|
| **① 수동(폰)** | `out/` 폴더를 Drive로 동기화 → 폰에서 사진 선택 + `caption.txt` 붙여넣기 | 준비할 것 없음. 앱 기능(음악 등)을 전부 쓸 수 있음 | 바로 가능 |
| **② 브라우저 자동** | 딸깍업로더 `instagram.py`의 `post()`로 이미지 최대 10장 + 캡션 게시 | **테스트 계정에서 [공유하기] 실제 클릭 1회 검증**이 선행 조건. 예약은 업로더가 그 시각까지 기다렸다 올리는 방식이라 PC가 켜져 있어야 함 | 코드 있음, 미검증 |
| **③ Graph API 예약** | Content Publishing API로 무인 예약 | 프로페셔널 계정 + 페이스북 페이지 + Meta 앱 + 장기 토큰(60일 갱신). 이미지는 **공개 URL의 JPEG**여야 함 | 미착수 |

③의 공개 URL 문제는 이 저장소가 이미 쓰는 **Cloudflare Pages(또는 R2)에 발행용 JPEG를 올려 URL을 만드는 방식**으로 풀 수 있습니다. 이 방법은 아직 시험하지 않았습니다. 하루 게시 한도 등 API 제약은 문서마다 수치가 달라서, 착수 시점에 Meta 공식 문서로 다시 확인해야 합니다. ②나 ③으로 넘어가기 전에는 같은 소재를 ①과 자동 방식으로 각각 올려 도달 차이를 비교합니다(API 게시물 불이익 여부 미검증).

### 3-8. 성과 → 개선
- 내 게시물의 24시간·72시간 좋아요·댓글을 수집기로 다시 모읍니다. 본인 계정이면 인사이트로 저장·공유 수까지 봅니다.
- 제목 공식별·소재별 평균을 내서 월 1회 프롬프트를 개정합니다. 개정 전후를 비교해 이긴 쪽만 반영합니다.

1단계에서 화면(그리드→모달)을 바로 만들지 않고 대화형으로 시작하는 이유는 두 가지입니다. 첫째, DESIGN.md(09-24)보다 나중인 09-29에 남긴 피드백("굳이 툴을 안만들더라도 내가 말하면 너가 알아서 기획하고 벤치마킹하고, 설계해서 제작 할때 자산으로 사용할 수 있으면 돼", 메모리 `data-as-asset-no-ui.md`)과 맞습니다. 둘째, 카피 API 비용과 키 관리 없이 바로 결과물을 볼 수 있습니다. DESIGN.md의 SHORT_TUBER식 화면은 나중에 "화면을 만들어 달라"고 할 때 같은 `out/` 규격 위에 얹으면 됩니다.
